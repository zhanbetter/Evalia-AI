# 数据归属 + 删除保护 · 交付说明

> 功能：四张核心用户数据表记录创建者（`created_by`），删除接口校验「创建者或管理员才能删」，其余人只读。
> 日期：2026-08-21

---

## 1 背景与原则

平台是共享数据模式（多用户共用同一批数据集/模型/评估器），此前任何登录用户都能删掉别人创建的资源。本功能做**轻量删除保护**，不做完整数据隔离：

- **删除**：创建者本人或管理员可删；历史无归属数据仅管理员可删。
- **创建 / 更新 / 查询**：仍全员可见可操作，行为不变。

## 2 权限规则

| created_by | 当前用户 | 结果 |
| --- | --- | --- |
| 有值 | 创建者本人 | ✅ 可删 |
| 有值 | 管理员 | ✅ 可删 |
| 有值 | 其他普通用户 | ❌ 拒绝：`无权删除该X：仅创建者或管理员可操作` |
| NULL（历史数据） | 管理员 | ✅ 可删 |
| NULL（历史数据） | 普通用户 | ❌ 拒绝：`该X为历史数据（无归属），仅管理员可删除` |

统一在 `com.eval.common.util.OwnershipUtil.assertCanDelete(ownerId, ctx, resourceName)` 中实现，四个删除入口共用。

## 3 涉及接口

### 归属记录（创建时写入 created_by）

| 接口 | 说明 |
| --- | --- |
| `POST /api/datasets/upload` | 上传数据集（含提交新版本），归属=管理员/当前用户 |
| `POST /api/models` | 新增模型配置 |
| `POST /api/prompts` | 新增评估器 |
| `POST /api/tasks` | 创建评测任务（仅记归属，无删除端点） |

取值来自登录态：Controller 通过 `@RequestAttribute("eval.auth") AuthContext ctx` 读取拦截器注入的用户，传 `ctx.getUserId()` 给 service。

### 删除保护（删除前校验归属）

| 接口 | 校验资源 |
| --- | --- |
| `DELETE /api/datasets/{id}` | 数据集 |
| `DELETE /api/datasets/items/{itemId}` | 所属数据集（先查条目→数据集再校验） |
| `POST /api/datasets/{id}/items/batch-delete` | 所属数据集 |
| `DELETE /api/models/{id}` | 模型配置 |
| `DELETE /api/prompts/{id}` | 评估器 |

## 4 数据库迁移

已有环境执行（在项目根目录运行）：

```bat
mysql --default-character-set=utf8mb4 -uroot -p1234 llm_eval -e "source llm-eval-server/sql/migration_user_ownership.sql"
```

不确定缺哪些迁移时，直接跑全量幂等补丁（已并入第 15 批）：

```bat
mysql --default-character-set=utf8mb4 -uroot -p1234 llm_eval -e "source llm-eval-server/sql/migration_patch_all.sql"
```

也可以把重定向整体交给 cmd（`<` 必须在引号里面，否则 PowerShell 先报 ParserError）：

```bat
cmd /c "mysql --default-character-set=utf8mb4 -uroot -p1234 llm_eval < llm-eval-server\sql\migration_user_ownership.sql"
```

⚠️ 不要用 PowerShell 的 `Get-Content | mysql`（中文环境会按 GBK 转码损坏数据）。

字段位置：`eval_dataset.created_by`（total_count 后）、`eval_model_config.created_by`（status 后）、`eval_prompt.created_by`（status 后）、`eval_task.created_by`（progress 后）。全新部署直接走 `init.sql`，四表已包含该列。

## 6 备注 / 后续可做

- 更新（PUT）接口暂不校验归属——本次按批准范围只保护删除。若后续要「非创建者不可编辑」，在 update 前加同样的 `assertCanDelete` 即可（约 4 处）。
- 已有历史数据（创建于登录功能之前）`created_by` 均为 NULL，管理员可直接删；如需移交归属可人工 UPDATE。
- 若未来要做数据隔离，建议按 `dataset` 维度扩展：单用户只看到自己的数据集/模型/评估器/任务（列表接口加 `created_by = 当前用户` 过滤），当前删除保护是其前提。
