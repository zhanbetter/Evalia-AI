# 登录 / 注册 · 交付说明

> 功能：Evalia-AI 评测平台接入登录注册鉴权。邀请码模式 + JWT 无状态令牌，首个注册用户自动成为管理员。
> 日期：2026-08-21

---

## 1 功能一览

| 模块 | 说明 |
| --- | --- |
| 注册 | 邀请码必填（与配置 `eval.security.register-code` 一致），用户名唯一，密码 BCrypt 加密 |
| 登录 | 用户名 + 密码，签发 JWT（默认 72 小时有效） |
| 角色 | **首个注册用户自动 ADMIN**，其后注册均为 USER（当前所有页面访问权限一致，角色字段预留给后续管控） |
| 鉴权 | Spring `HandlerInterceptor` 拦截 `/api/**`，放行 `login`/`register`/OPTIONS；请求头 `Authorization: Bearer <token>` |
| 前端守卫 | 未登录访问任何页面 → 跳 `/login?redirect=...`；登录后回到原页面 |
| 401 处理 | axios 拦截 HTTP 401 → 清本地登录态 → 跳登录页并提示「登录已过期」 |
| 侧边栏 | 新增用户区（头像/昵称/角色标签，「退出登录」下拉）；品牌改为「Evalia-AI 评测平台」 |
| 标注身份 | 人工审核 / 金标准标注的「标注者」默认自动带入登录用户名（仍可手动修改并记忆） |
| 登录页 | `/login`：左侧品牌面板 + 登录/注册 Tab，支持回车提交 |

## 2 数据库迁移

已有环境执行（新克隆直接 `init.sql`，已并入该表）。在项目根目录运行（`D:\postgraduate\project\大模型\大模型评测平台`）：

```bat
mysql --default-character-set=utf8mb4 -uroot -p1234 llm_eval -e "source llm-eval-server/sql/migration_user_auth.sql"
```

若不确定环境缺哪些迁移，直接跑全量幂等补丁兜底（已含第 14 批 eval_user 表）：

```bat
mysql --default-character-set=utf8mb4 -uroot -p1234 llm_eval -e "source llm-eval-server/sql/migration_patch_all.sql"
```

也可以把重定向整体交给 cmd（`<` 必须在引号里面，否则 PowerShell 先报 ParserError）：

```bat
cmd /c "mysql --default-character-set=utf8mb4 -uroot -p1234 llm_eval < llm-eval-server\sql\migration_user_auth.sql"
```

⚠️ 不要用 PowerShell 的 `Get-Content | mysql`（中文环境会按 GBK 转码损坏数据），也不要把 `<` 放在引号外面单独写。

## 3 配置项（application.yml → eval.security）

| 配置 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `register-code` | `EVAL_REGISTER_CODE` | `evalia80` | 注册邀请码；置空 = 关闭自助注册（只能登录） |
| `jwt-secret` | `EVAL_JWT_SECRET` | 开发默认密钥 | HS256 签名密钥，**生产务必用环境变量覆盖** |
| `jwt-expire-hours` | `EVAL_JWT_EXPIRE_HOURS` | `72` | 令牌有效期（小时） |

## 4 联调步骤

1. 执行迁移（见上），重启后端（`start-dev.cmd` 或单独重启 8080）。
2. 浏览器打开前端 → 未登录会落到 `/login`。
3. 首次访问切到「注册」Tab，用邀请码 `evalia80` 注册第一个账号 → 自动成为管理员。
4. 登出后再注册第二个账号 → 普通用户。两个账号分别进「人工审核 / 金标准标注」时，标注者默认带各自登录名。
5. 令牌过期或手动改 localStorage 删掉 `eval-token` 后 F5 → 被路由守卫/401 拦回登录页。

## 6 备注 / 后续可做

- 登出是无状态语义（前端删 token 即可，后端 `POST /api/auth/logout` 保留占位）。如需服务端强制失效，可后续加 Redis 黑名单。
- 邀请码为静态配置；若需一次性邀请码（`invite_code` 表、每人一个、可回收），约 +0.5~1h 可改造成动态码。
- 角色当前未做接口级权限区分（ADMIN/USER 均可访问全站），后续可据此收敛「管理类操作仅管理员」。
